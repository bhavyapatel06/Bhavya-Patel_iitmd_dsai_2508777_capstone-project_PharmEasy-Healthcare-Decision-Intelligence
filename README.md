# PharmEasy Healthcare Decision Intelligence

**Capstone:** Minor in Artificial Intelligence & Data Science, IIT Mandi  
**Scope:** Synthetic healthcare-operations data; care-plan cost estimation, appointment no-show prediction, customer segmentation, model comparison and neural-network sizing.

> **Important scope and safety note:** This repository uses only the synthetic dataset generated by the supplied `generate_data.py`. It contains no PharmEasy customer records and says nothing about PharmEasy's actual operations or performance. The models are for operational scheduling and cost-planning exercises only; they are not clinical models and must not be used to diagnose, treat or make healthcare decisions.

## How to run

Use Python 3.10 or newer. The only third-party dependency is the pinned NumPy version in `requirements.txt`. Run every command from the repository root.

After cloning the repository, open a terminal in the repository root and run these commands in order. The commands below use Windows PowerShell; for macOS/Linux, use `source .venv/bin/activate` for the activation step.

```powershell
# 1. Create and activate a virtual environment
python -m venv .venv
.venv\Scripts\Activate.ps1

# 2. Install the pinned dependency
python -m pip install --upgrade pip
pip install -r requirements.txt

# 3. Regenerate the supplied synthetic dataset
python generate_data.py

# 4. Run the four project parts in dependency order
python part1.py
python part2.py
python part3.py
python part4.py

# 5. Run the offline acceptance checks
python validate_outputs.py
```

For macOS/Linux, activate the environment with `source .venv/bin/activate` instead of the Windows activation command. The generator should print exactly:

```text
800 10 170 e26b46e82f1a1af44dcabc133050802e
```

The scripts write their results to `outputs/`. `validate_outputs.py` checks the generator hash, required result keys, CSV headers and row counts, assignment checkpoints and segment totals. The scripts do not download data, call external APIs or require network access after NumPy is installed. `part2.py` owns the stratified split and training-only standardisation; `part4.py` independently reproduces the same deterministic split and Part 2 model settings so that it can be run as a standalone script after Part 2. Run the scripts in the order above to regenerate all committed outputs.

## Part 1 findings

### Cost estimation and hypothesis test

The dataset contains **800** records. The sample mean care-plan cost is **8.9382 thousand INR** (approximately **INR 8,938.20**) and the sample standard deviation is **9.1723 thousand INR**. The 95% confidence interval for the mean is **8.3026 to 9.5738 thousand INR**.

The planning claim is that the population mean is 8.0 thousand INR. The computed z-statistic is **2.8930**, whose absolute value exceeds the two-tailed 5% critical value **1.96**. Therefore, this test rejects the null hypothesis. The observed sample mean is **0.9382 thousand INR**, or approximately **INR 938.20**, above the planning value. This difference is statistically significant under the task's assumptions, but its practical importance depends on the number of patients budgeted and the organisation's cost tolerance.

A Type I error here would mean concluding that the average care-plan cost differs from INR 8,000 when the true population average is actually INR 8,000.

### Sample-size implication

The required sample size for a 95% estimate with a margin of error of INR 500 is **1,293** records, compared with **800** currently available. The current synthetic sample is therefore 493 records short of the requested precision target under the assignment's sample-size formula.

### Regression and gradient descent

The simple regression of care-plan cost on average past bill has slope **0.6701**, intercept **−3.6598** and R² **0.5196**. The closed-form fit and the 500-update gradient-descent fit agree to a slope gap of **0.0000** at the required four-decimal reporting precision. Gradient descent approaches the same least-squares optimum because the objective is a convex quadratic in the slope and intercept, and the specified learning rate and standardised input allow it to converge.

The raw residual standard-deviation ratio (upper fitted-value half divided by lower fitted-value half) is **3.7525**, indicating a pronounced funnel: residual spread is substantially larger at higher fitted values. After the log-log regression, the ratio is **1.0396**, much closer to 1; on this diagnostic the log transformation largely removes the funnel pattern.

### Multiple regression

Applying the assignment's mechanical absolute-coefficient cutoff of 0.05 (excluding the intercept), the predictors above the cutoff are **ln(X4)** (β₁ = 1.1576), **X2** (β₃ = 0.0940), **X3** (β₄ = 0.1067) and **X6** (β₆ = 0.1518). This is only the requested thresholding rule, not a ranking of importance: the predictors use different units.

The multiple model's adjusted R² is **0.7403**, compared with **0.6561** for the one-predictor log-log model. The extra predictors improve adjusted in-sample fit on this synthetic dataset, although this alone does not establish causal relationships or out-of-sample performance.

## Part 2 findings

### Training and learning-rate comparison

The pinned stratified split contains **560 training rows** (119 positives) and **240 test rows** (51 positives). Standardisation uses only the training-set means and sample standard deviations; the same values are applied to the test set.

After 200 updates, the training losses are **0.5091** for η = 0.01, **0.3776** for η = 0.1 and **0.3703** for η = 1.0. In this run the smallest learning rate is still converging more slowly, while the larger rate makes faster progress without diverging over the specified 200 updates. A larger learning rate is not universally better; it must be checked for instability on the actual objective.

### Logistic-regression interpretation

The three largest absolute standardised logistic weights are **X3 = 0.9013**, **X1 = −0.5554** and **X2 = 0.5505**. The largest odds ratio is for X3: **2.4629**. Holding the other standardised predictors fixed, a one-training-standard-deviation increase in copay-burden ratio multiplies the modelled odds of a no-show by about 2.46. This is an association in the synthetic model, not a causal effect.

### Threshold and metric comparison

At τ = 0.5, logistic regression has accuracy **0.8042**, only modestly above the all-negative baseline accuracy **0.7875**. Accuracy alone is weak here because only 51 of 240 test records are positive; a model can achieve a seemingly high score by predicting the majority class while missing no-shows.

Lowering the logistic threshold from 0.5 to 0.3 increases recall from **0.4706** to **0.7451**, while precision decreases from **0.5455** to **0.4634**. At τ = 0.3, logistic regression has **F1 = 0.5714** and **recall = 0.7451**. KNN (selected **K = 5** by the specified five-fold training-only cross-validation) has **F1 = 0.3696** and **recall = 0.3333** on the test set.

### Cost-sensitive threshold decision

The minimum training cost occurs at **τ = 0.15**. On the held-out test set, the logistic model's cost at this threshold is **INR 6,050**, compared with **INR 11,800** at τ = 0.5 and **INR 20,400** if nobody is flagged. The cost threshold is selected on training data to avoid using the test labels to tune a decision rule; the test set is retained for an honest final evaluation. This is the assignment's fixed cost model (INR 50 per false alarm and INR 400 per missed no-show), not a measured real-world financial impact.

## Part 3 findings

### K-means and elbow analysis

The WCSS values for K = 2 through 6 are **2262.6753**, **1602.8471**, **1494.7732**, **1323.7157** and **1278.1691**. The successive drops are therefore:

- WCSS(2) − WCSS(3) = **659.8282**
- WCSS(3) − WCSS(4) = **108.0739**
- WCSS(4) − WCSS(5) = **171.0575**
- WCSS(5) − WCSS(6) = **45.5466**

The pinned elbow rule selects **K = 3**: the drop from K = 3 to K = 4 is less than half the preceding drop. The later drops do not shrink steadily, which is possible because the assignment prescribes deterministic initial centroids rather than a search for the global optimum. The three clusters are nevertheless profiled using K = 3 as explicitly required.

### Hierarchical clustering

At the largest-gap cut, single linkage gives **E1**, **E2+E3+E6**, **E4** and **E5** (four clusters). Complete linkage gives **E1+E4+E5** and **E2+E3+E6** (two clusters). Single linkage uses the closest pair of members across two clusters, so a short chain of close pairs can merge one side while leaving other cohorts separate at the cut. Complete linkage uses the farthest cross-cluster pair, so it waits until all members are sufficiently close and produces a different merge-height sequence and cut.

### Principal component analysis

The standardised five-feature matrix has mean vector approximately **[0, 0, 0, 0, 0]** after centring. PC1 is driven positively by **X1 (+0.5317)** and **X5 (+0.4418)**, and negatively by **X3 (−0.5187)**, **X2 (−0.4100)** and **X4 (−0.2916)**. The first two components explain **75.93%** of the variance; **three components** are required to reach at least 80% (86.16%).

The mean PC1 scores are **A = 1.7773**, **B = −0.7831** and **C = −1.6709**. In this component orientation, segment A lies toward longer registration and higher adherence, while C lies toward higher copay burden and lower tenure/adherence; B is intermediate. PCA loadings describe a direction of variation, not a causal explanation.

## Part 4 findings

### Split purity and decision stump

**S4 (X1 ≤ 24)** is the best split by both information gain (**0.1252**) and Gini gain (**0.0606**). Its yes branch contains 188 training rows with 86 positives (positive rate **0.4574**); its no branch contains 372 rows with 33 positives (positive rate **0.0887**). This split reduces impurity most among the four candidates. A decision tree grown until every leaf is pure can memorise noise and small-sample quirks; a maximum-depth limit or a minimum-leaf-size rule can restrict its growth.

### Model comparison and voting

At the task-prescribed τ = 0.3 comparison threshold, logistic regression has **F1 = 0.5714** and **recall = 0.7451**; KNN has **F1 = 0.3696** and **recall = 0.3333**; the stump has **F1 = 0.5532** and **recall = 0.7647**; hard voting has **F1 = 0.5344** and **recall = 0.6863**; and soft voting has **F1 = 0.5507** and **recall = 0.7451**. Combining the three models did not improve F1 over logistic regression in this test split. Logistic regression is therefore the strongest of these five by F1, while the stump has the highest recall.

### AdaBoost calculation

Round 1 has weighted error **0.2500** and α₁ = **0.5493**. After round 1 normalisation, the two misclassified points (3 and 7) carry a combined weight of **0.5000**. Round 2's weighted error falls to **0.1667**, giving α₂ = **0.8047**; h2 receives more weight because it performs better under the reweighted distribution created after round 1. The two-round ensemble accuracy on the eight supplied points is **0.7500**.

### Neural-network architecture sizing

**Model A — 28 × 28 grayscale image input, 10 output classes**

| Layer/stage | Output shape | Parameters |
|---|---:|---:|
| Input | 28 × 28 × 1 | 0 |
| Conv1 (5 × 5, 6 filters, padding 2) | 28 × 28 × 6 | 156 |
| ReLU | 28 × 28 × 6 | 0 |
| Max-pool (2 × 2, stride 2) | 14 × 14 × 6 | 0 |
| Conv2 (5 × 5, 16 filters, no padding) | 10 × 10 × 16 | 2,416 |
| ReLU | 10 × 10 × 16 | 0 |
| Max-pool (2 × 2, stride 2) | 5 × 5 × 16 | 0 |
| Flatten | 400 | 0 |
| Dense1 (32 neurons) | 32 | 12,832 |
| Dense output (10 neurons) | 10 | 330 |

The CNN has **15,734** trainable parameters. The alternative MLP (784 → 16 → 16 → 10) has **13,002**. For the larger 128 × 128 × 3 example, the fully connected layer has **50,332,672** parameters, whereas the 64-filter 3 × 3 convolution has **1,792**. Convolution uses local connectivity and shared filter weights, so its parameter count does not scale with the number of image positions in the same way as a fully connected layer.

**Model B — recurrent text model:** Wₓₕ has shape **128 × 64**, Wₕₕ has shape **128 × 128**, and Wₕᵧ has shape **16 × 128**. The bias vectors have 128 and 16 entries. The total is **26,768** parameters. The same recurrent weights are reused at every time step, so increasing sequence length increases computation but not the number of learned parameters.

For the 10-class image-routing task, ReLU is a reasonable hidden-layer activation; use softmax at the output with categorical cross-entropy for mutually exclusive classes. A very deep plain network can suffer vanishing gradients, making early layers learn very slowly; skip/residual connections provide a shorter identity path for information and gradients and make optimisation easier.

## Limitations

1. **Synthetic evidence:** all 800 records are generated by a fixed script. The distributions, relationships, and model results do not represent real PharmEasy patients or real service operations.
2. **Limited validation:** the classifier is evaluated on one pinned stratified 70/30 split, with only 51 positive test cases. Performance may vary on another sample or in a changing operational environment.
3. **Assumed costs:** INR 50 per false alarm and INR 400 per missed no-show are assignment assumptions, not measured costs. A real threshold requires finance and operations validation.
4. **No causal interpretation:** regression coefficients, odds ratios, PCA loadings and clusters describe patterns in generated data; they do not establish why a patient misses an appointment or what intervention will change behaviour.
5. **No deployment controls:** this capstone does not implement production data governance, privacy controls, monitoring, drift detection, model calibration, human escalation or fairness review. Those are prerequisites for any real operational deployment.
6. **Clustering sensitivity:** K-means uses the assignment's pinned initial centroids and deterministic rules. Its result is reproducible for grading but is not guaranteed to be the global minimum-WCSS solution.
